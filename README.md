# Raspbot V2 simulated-camera PID line follower

The Gazebo Raspbot V2 has a **simulated camera** mounted on top. It views a continuous black tape route with four smooth **45° turns**: left, right, right, then left. The `line_offset.py` vision algorithm detects the tape and opens live camera, Sobel, and mask windows. A small PID loop uses the normalized camera deviation to steer the robot. No physical Raspbot or USB camera is used.

The controller follows the structure of the supplied `wafer_cart` files:

- `raspbot_chassis/raspbot_chassis/hardware.py` reads camera error and sends chassis velocity commands.
- `raspbot_chassis/raspbot_chassis/pid.py` contains the PID calculation.
- `raspbot_chassis/raspbot_chassis/main.py` runs the 20 Hz control loop.

The robot starts centered on the first straight section and drives slowly at 0.02 m/s (one quarter of the earlier speed) so the camera PID has more time at each bend. It stops when the camera loses the line or stops producing fresh data. The route is finite, so it will stop at the end. The turns use a 0.45 m radius. Tape geometry is generated by `raspbot_chassis/scripts/generate_path.py`.

## Run in Ubuntu 26.04

Use ROS 2 Lyrical and Gazebo Jetty. Close any old Gazebo demo first. If ROS is missing, run `bash raspbot_chassis/scripts/install_ubuntu.sh` once from this repository.

```bash
source /opt/ros/lyrical/setup.bash
if [ ! -f /etc/ros/rosdep/sources.list.d/20-default.list ]; then sudo rosdep init; fi
rosdep update --rosdistro lyrical
rosdep install --from-paths raspbot_chassis --ignore-src -r -y --rosdistro lyrical
colcon --log-base log-pid build --base-paths ./raspbot_chassis \
  --build-base build-pid --install-base install-pid \
  --symlink-install --packages-select raspbot_chassis
source install-pid/local_setup.bash
ros2 launch raspbot_chassis chassis.launch.py
```

The default launch starts Gazebo, the simulated camera, the live vision windows, and the PID controller. To inspect the camera without driving, launch with `drive:=false`. Press `s` in a vision window to save a screenshot; press `q` to close the vision windows. `show_view:=false` keeps publishing `/camera/annotated` without opening OpenCV windows.

## Plot a run and tune the PID

The controller writes `~/raspbot_pid.csv` at 20 Hz. Let the robot reach at least the first bend (about 25 seconds at the current speed), stop the launch with Ctrl-C, then plot the run from the source directory:

```bash
python3 raspbot_chassis/scripts/plot_pid.py
```

The script saves `~/raspbot_pid.png` with camera error, P/I/D contributions, commanded versus measured yaw rate, and odometry over the tape path. Share the PNG and CSV to tune from the actual VM run. The plot script uses `python3-matplotlib`, installed by the `rosdep install` command above.

For **model-based** Bode and Nyquist plots using the gains and speed recorded in that CSV:

```bash
python3 raspbot_chassis/scripts/plot_frequency_response.py \
  --csv ~/raspbot_pid.csv --output-dir ~
xdg-open ~/raspbot_bode_model.png
xdg-open ~/raspbot_nyquist_model.png
```

These frequency plots use a linearized camera-and-robot model derived from the SDF camera height and field of view. They are **not measured** from the tracking run; image-processing delay, steering saturation, tape loss, and unknown Gazebo dynamics are omitted. Use them to compare candidate gains, then judge the actual behavior from `~/raspbot_pid.png`. A measured Bode/Nyquist analysis would need a deliberate frequency-sweep input and its recorded response.

You can change gains without editing code or rebuilding:

```bash
ros2 launch raspbot_chassis chassis.launch.py kp:=0.08 ki:=0.0 kd:=0.002
```

Defaults are `kp:=0.04`, `ki:=0`, `kd:=0.002`, `speed:=0.02`, and `max_correction:=0.02`. `steering_sign:=1` is the default; use `steering_sign:=-1` for a diagnostic run if the plot shows the robot turning **away** from the tape. Check steering direction before increasing gains. Each new launch overwrites `~/raspbot_pid.csv`, so copy it before comparing runs.

## Transfer to the Ubuntu VM

These local edits are not included in an older VM checkout. Transfer `dist/raspbot-frequency-plots-ubuntu26.04.zip` to the VM. If UTM VirtFS/9p sharing is enabled for this project's `dist` folder:

```bash
ls -lh /mnt/utm/raspbot-frequency-plots-ubuntu26.04.zip
mkdir -p ~/raspbot-pid
unzip -o /mnt/utm/raspbot-frequency-plots-ubuntu26.04.zip -d ~/raspbot-pid
cd ~/raspbot-pid/Wafer-Transport-Demo
```

Only run the build commands after the `ls` and `cd` commands succeed.

## Controller interface

| Topic | Type | Meaning |
|---|---|---|
| `/camera/image_raw` | `sensor_msgs/msg/Image` | Gazebo camera feed. |
| `/camera/annotated` | `sensor_msgs/msg/Image` | Live feed with tape and deviation drawn. |
| `/line/offset_normalized` | `std_msgs/msg/Float32` | Camera deviation; positive means tape right, NaN means lost. |
| `/line/visible` | `std_msgs/msg/Bool` | Tape detected. |
| `/cmd_vel` | `geometry_msgs/msg/Twist` | PID drive command. |
| `/odom` | `nav_msgs/msg/Odometry` | Robot motion feedback. |

The current PID uses proportional and derivative terms; integral gain starts at zero. The launch arguments above let you tune them between runs.
